# 02 · 独立路径分析（三种方法）

> 前置：[01-控制流图与圈复杂度](01-控制流图与圈复杂度.md)
> 结论：圈复杂度 V(G) = 18，需要 **18 条线性无关路径**构成基本路径集。

---

## 0. 为什么需要三种方法

三种方法回答的是同一个问题的不同侧面：

| 方法 | 回答的问题 | 产出 |
|---|---|---|
| 基本路径法（McCabe） | 「哪 18 条路径够用？」 | 可直接写用例的路径集合 |
| 图矩阵法 | 「这个数是怎么从结构里算出来的？」 | 与流图结构挂钩的计数过程 |
| Z 路径法（判定组合展开） | 「不归约的话一共有多少条？」 | 全路径数量，说明为何必须归约 |

三者互相印证：方法一给集合，方法二给计数，方法三给归约的必要性论证。

---

## 1. 方法一：基本路径法（McCabe 基线路径法）

### 1.1 步骤

1. 选一条**基线路径**（尽可能包含多的节点）；
2. 每次改变一个判定节点的走向，得到一条新路径；
3. 要求每条新路径**至少引入一条此前未覆盖的边**；
4. 重复直到所有边被覆盖——此时路径数恰好等于 V(G) = 18。

### 1.2 基线路径

选取「所有专项附加扣除全部不生效、应纳税所得额为负」的路径作为基线：

```
P3: N1 → N2 → N4 → N6 → N7 → N9 → N11 → N13 → N15 → N17 → N19
        → N21 → N23 → N24 → N25 → N39 → N40
```

该路径覆盖 16 条边（E1、E3、E6、E8、E10、E13、E16、E19、E22、E25、E28、E31、E33、E34、E36、E56），
并确立了「所有判定走假分支」的基准走向。

### 1.4 完备性验证

| 检查项 | 结果 |

| 18 条路径的边并集 | 覆盖全部 56 条边（E1–E56）✓ |
| 线性无关性 | 每条路径含一条其他路径都不含的边，故线性无关 ✓ |

## 2. 方法二：图矩阵法

### 2.1 邻接矩阵（完整形式）

流图共有 40 个节点，完整邻接矩阵为 40 × 40 的 0/1 矩阵 `A`，其中 `A[i][j] = 1` 表示存在边 `Ni → Nj`。

由于矩阵规模大且稀疏（仅 56 个非零元），工程上使用其**压缩形式**——判定节点后继表。

### 2.2 判定节点后继矩阵（压缩形式）

| 判定节点 | 真后继 | 假后继 | 出度 |
|---|---|---|---|
| ① N2 | N3 | N4 | 2 |
| ② N4 | N5 | N6 | 2 |
| ③ N7 | N8 | N9 | 2 |
| ④ N9 | N10 | N11 | 2 |
| ⑤ N11 | N12 | N13 | 2 |
| ⑥ N13 | N14 | N15 | 2 |
| ⑦ N15 | N16 | N17 | 2 |
| ⑧ N17 | N18 | N19 | 2 |
| ⑨ N19 | N20 | N21 | 2 |
| ⑩ N21 | N22 | N23 | 2 |
| ⑪ N24 | N25 | N26 | 2 |
| ⑫ N26 | N27 | N28 | 2 |
| ⑬ N28 | N29 | N30 | 2 |
| ⑭ N30 | N31 | N32 | 2 |
| ⑮ N32 | N33 | N34 | 2 |
| ⑯ N34 | N35 | N36 | 2 |
| ⑰ N36 | N37 | N38 | 2 |
| **合计** | | | **34** |

### 2.3 由矩阵导出圈复杂度

图矩阵法的计数公式：

```
V(G) = Σ(判定节点出度) − 判定节点数 + 1
     = 34 − 17 + 1
     = 18
```

**为什么这个式子成立**：把流图看作有向图，`Σ出度 = 边数 = 56`；对只有二值判定的结构化流图，`边数 = 判定节点数 + 非判定节点数 − 1`，代入即得 `E − N + 2`，与边点法等价。矩阵法的作用是把计数过程落到**结构数据**上，便于工具自动化实现。

### 2.4 矩阵法的工程价值

1. **可自动化**：只要解析出判定节点后继表，就能算出 V(G)，无需手工画图；
2. **可定位复杂度热点**：按行统计出度分布即可发现「哪个方法的分支最多」——本项目 41% 的判定节点集中在税率阶梯一段；
3. **可作为 CI 门禁**：把 V(G) 作为静态检查指标，超过阈值即阻断合并。

> **本项目的实践**：`tests/unit/test_control_flow_metrics.py` 用 Python `ast` 模块解析源码，按本节的计数规则自动算出判定节点数与 V(G)，并与本文档的数字比对。文档一旦与代码脱节，CI 立即报错。
>
> 同一套度量也用于验证重构收益：`src/tax_service/core/oracle.py` 把税率阶梯改为表驱动遍历后，该段判定节点由 7 个降到 3 个；方法职责拆分后单方法最高圈复杂度由 **18 降到 9**，全部低于阈值 10。详见 [01 第 5 节](01-控制流图与圈复杂度.md#重构收益实测)。

## 3. 方法三：Z 路径法（判定组合展开）

### 3.1 展开原则

流图中 17 个判定节点**互不嵌套**（全部是顺序的 if / if-else if 链），因此全路径数等于各判定节点有效分支数的**乘积**。

其中：

- 判定 ①、② 的真分支直接 `throw` 终止，不再有后续分支，故有效分支数计为 **1**（只有「假」能继续）；
- 其余判定节点按各自的有效出口数计数。

### 3.2 分支因子表

| 判定节点 | 分支数 | 有效出口 | 说明 |
|---|---|---|---|
| ① N2 `person == null` | 2 | **1** | 真分支终止流程 |
| ② N4 `salary < 0` | 2 | **1** | 真分支终止流程 |
| ③ N7 `children_Num > 0` | 2 | **2** | 真 / 假 |
| ④⑤ N9 / N11 `is_KeepStu` | — | **3** | 链式：`==1` / `==2` / 两者皆非 |
| ⑥ N13 `is_HouseLoans` | 2 | **2** | 真 / 假 |
| ⑦⑧⑨ N15 / N17 / N19 `is_RentHouse` | — | **4** | 链式：`1` / `2` / `3` / 皆非 |
| ⑩ N21 `is_SupportingElderly` | 2 | **2** | 真 / 假 |
| ⑪–⑰ N24–N36 税率阶梯 | — | **8** | 链式含最终 `else`：7 个条件 + 1 个兜底 |

### 3.3 全路径数量

```
全路径数 = 1 × 1 × 2 × 3 × 2 × 4 × 2 × 8
         = 768
```

**结论：该方法的完整路径组合共有 768 条。**

### 3.4 为什么必须归约到 18 条

| 指标 | 值 |
|---|---|
| 全路径组合数 | 768 |
| 独立路径数 V(G) | 18 |
| 压缩比 | 768 / 18 ≈ **42.7 : 1** |

这正是「路径爆炸」问题的具体体现：

1. **不可穷举**：768 条全路径逐条写用例不现实，且其中大量路径的差异只体现在不影响结果的组合上；
2. **基本路径集已足够**：18 条线性无关路径覆盖了全部 56 条边，即**覆盖了所有可执行语句和所有判定走向**；
3. **独立路径 ≠ 全路径**：独立路径保证「每条边至少被执行一次」，但不保证「所有组合被执行」。

### 3.5 这个差距正是本项目缺陷 D1 的来源

第 3.4 节第 3 点是本项目最重要的发现：

> **18 条独立路径 100% 覆盖了所有判定走向，却没有发现「第 3–7 级速算扣除数少计 1300 元」这个缺陷。**

原因在于：路径覆盖只关心「控制流走到哪」，不关心「算术表达式算得对不对」。白盒路径覆盖能发现的是**分支遗漏、条件写反、不可达代码**类缺陷；而常量抄错、公式写错属于**数据与算式缺陷**，必须靠黑盒需求验证来发现。

实证见 [03-白盒测试用例](03-白盒测试用例.md) 第 4 节与 [05-缺陷分析报告](05-缺陷分析报告.md)。

## 4. 三种方法结论对照

| 方法 | 输出 | 结果 |
|---|---|---|
| 基本路径法 | 基本路径集（可直接写用例） | 18 条路径，覆盖全部 56 条边 |
| 图矩阵法 | 圈复杂度计数 | Σ出度 34 − 判定 17 + 1 = 18 |
| Z 路径法 | 全路径组合数 → 归约依据 | 768 → 18，压缩比 42.7:1 |

三者一致，**基本路径集为 18 条**，与 [01](01-控制流图与圈复杂度.md) 中三种复杂度算法得出的 V(G) = 18 完全吻合。

## 一、核心亮点与结论

1. **白盒与黑盒的认知实证**：在个税核心计算逻辑中，控制流图圈复杂度 $V(G)=18$。白盒测试**100% 覆盖全部 18 条独立路径**（语句/分支均为 100%），发现了 **0 个缺陷**；而黑盒需求预言测试发现了 **5 个重大缺陷**。实证证明：**覆盖率是准入底线，而非质量证明**；白盒管控制流走向，黑盒管算术常数与业务真值。
2. **单一错误源的精确定位**：通过逐级累进增量对账，逆向定位出阶梯税率第 2→3 级增量多计 1300 元（理论应为 900 元，源码为 2200 元）；后续级距增量分毫不差，但错误随起算基数被原样线性放大并传播至全部高税率级次。
3. **并发幂等与数据一致性保护**：采用 `(user_id, idempotency_key)` 联合唯一约束与只读历史报文回填机制，根除了并发重放计算金额发生漂移的隐患；针对 SQLite 并发死锁，调优 WAL 模式与 `busy_timeout=5000ms` 支撑稳定并发。
4. **轻量测试平台与 WebSocket 实时流**：用例资产数据化维护，支持 JSONPath 表达式安全动态求值与单条故障隔离；后台工作线程与 asyncio 事件循环桥接，通过心跳与背压丢弃策略保障实时进度稳定广播。
5. **AI 赋能与四重契约防幻觉**：提出“模型提议、代码校验、人机回路、离线保底”闭环，以 OpenAPI 规范强类型把关模型生成用例（非法路径/方法/操作符 100% 拦截）；四状态机将故障精准路由至产品、用例、环境或数据责任人；构建协议与 DNS 预解析的三重 SSRF 防火墙。
6. **双模式自洽质量门禁**：在 `legacy` 模式下拦截缺陷并守住基线（32 条 xfail，0 意外失败）；切换到 `standard` 模式后 **630+ 条测试全部真实通过**，证明测试集兼备拦截力与守护力。

## 四、缺陷挖掘与可信证据

项目在重构与测试推演过程中共挖掘并逆向分析出 **9 项真实缺陷**：

| 编号 | 缺陷现象与本质归因 | 严重级别 | 发现分层与方法 | 修复与防护机制 |
|---|---|---|---|---|
| **D1** | **第 3~7 级超额累进税率速算扣除数系统性少计 1300 元**<br>源码第 2→3 级增量误算为 2200（理论为 900），导致月所得 ≥ 12000 元者每月多扣 1300 元 | 🔴 严重 | 黑盒 · 边界值分析<br>(`tests/unit/`) | 改用表驱动算法，由级距跨度与税率自动推导，彻底消除人工手抄常数隐患 |
| **D2** | **住房贷款利息与住房租金未做互斥校验，发生双重扣除**<br>政策规定二者不可同时享受，旧实现两个独立 `if` 导致每月多扣除高达 2500 元 | 🔴 严重 | 黑盒 · 判定表<br>(`tests/api/`) | 在领域层增加跨字段互斥校验，并在 HTTP 路由层自动映射为 422 业务违规 |
| **D3** | **兄弟姐妹数 `sibling_num = -1` 触发整数除零异常崩溃**<br>表达式 `2000 / (sibling_num + 1)` 未做下边界守卫，导致进程 500 崩溃 | 🔴 严重 | 契约 · 模糊测试<br>(`tests/contract/`) | Pydantic 层设置 `ge=0` 强约束，领域层增加非负前置防御断言 |
| **D4** | **继续教育 3600 元证书当年定额被当作月度项目逐月扣除**<br>年度一次性定额被按月循环扣减，全年累计扣除 43200 元（超额 12 倍） | 🟠 中度 | 黑盒 · 需求符合性<br>(`tests/unit/`) | 剥离年度专项扣除，建立月度与年度细则区分模型，月度测算仅保留 400 元学历扣除 |
| **D5** | **枚举参数传入非法值时被系统静默忽略，脏数据原样穿透**<br>如继续教育传入 `3`、租金传入 `9` 时未报错，伪装成“未享受扣除” | 🟠 中度 | 接口 · 参数校验<br>(`tests/api/`) | 接口层引入 `Literal[0, 1, 2]` 严格白名单，非法传参一律直接 422 阻断 |
| **D6** | **赡养老人分摊额整数截断导致纳税人微幅少扣**<br>3 人分摊 2000 元时每人取整扣 666 元，三人合计少扣 2 元，需求存在取整歧义 | 🟡 轻度 | 黑盒 · 规则核验<br>(`tests/unit/`) | 记录需求缺陷工单，统一采用标准整除规则并固化为对账基准 |
| **D7** | **浮点数税额向零截断取整未做规范定义**<br>如 89.97 元直接截断为 89 元而非四舍五入为 90 元，多单汇总时产生分位误差 | 🟡 轻度 | 黑盒 · 边界值<br>(`tests/unit/`) | 接口模型统一声明输出为整数，在文档中显式固定截断契约 |
| **D8** | **代码注释与执行逻辑冲突**（注释写税率 40%，实际代码执行 45%） | ⚪ 提示 | 代码静态审计 | 经税务核对国标实为 45%，修正注释消除代码阅读误导 |
| **D9** | **初值覆盖引发的死存储（Dead Store）**：`double tax = res;` | ⚪ 提示 | 代码静态审计 | 冗余初始值在所有分支均被覆盖，优化局部变量生命周期 |

## 五、双模式切换验证机制

为了证明自动化测试框架不是“硬编码答案让用例碰巧通过”，而是真正具备**缺陷拦截**与**回归守护**双重价值，TaxTestOps 支持双计算引擎自由切换：

```bash
# 模式 A：缺陷保留模式（Legacy Mode - 默认）
# 针对 9 项已知缺陷的需求断言自动打上 xfail(strict=True) 标记
pytest -q
# 输出：629 passed, 32 xfailed, 0 failed（精准守住已知缺陷基线，无任何意外报错）

# 模式 B：标准规范模式（Standard Mode）
# 切换至国标修正版引擎，原先因缺陷受影响的 32 处断言必须 100% 真实通过
TAX_CALCULATOR_IMPL=standard pytest -q
# 输出：631 passed, 29 skipped, 0 failed, 0 xfailed（全部通过，证明缺陷彻底修复且无意外回归）
```

## 六、测试平台与实时可观测

平台（运行于 `http://localhost:8100`）具备完整的用例生命周期管理与实时调度能力：

- **用例数据化**：将接口测试用例建模为存储实体，支持在 Web 界面进行免代码维护与标签筛选；
- **异步批次调度**：支持手动全量执行、标签批次执行与周期定时调度（`RunScheduler`）；
- **WebSocket 实时日志**：基于 `RunEventBroker` 订阅批次通道，工作线程执行状态秒级透传至浏览器；
- **健康度趋势度量**：自动聚合历史批次生成通过率与耗时变化曲线，提供 Flaky 疑似用例候选看板（自动筛查重试后成功的用例）。

## 七、AI 赋能测试开发实践

TaxTestOps 在 `src/tax_service/ai/` 中探索了大模型在测试开发领域的高置信度落地场景：

- **可信生成回路**：提供基于 OpenAPI 契约的离线规则生成器（`RuleBasedProvider`）与在线模型接入（`OpenAiCompatibleProvider`）；经由四重校验器严格审查，剔除幻觉路径与非法断言，AI 导入用例默认禁用（`enabled=False`），坚持人机闭环决策；
- **智能失败归因（Failure Triager）**：将失败信息自动流转至多状态机，分类为 `product_defect`（产品缺陷）、`test_issue`（用例编写失误）、`environment_issue`（环境网络故障）或 `data_issue`（数据约束冲突），输出根因假设与行动指引，实现故障秒级定向分流；
- **SSRF 纵深防御**：向被测端拉取 OpenAPI 规范时，严格执行协议白名单过滤、云元数据 IP 硬阻断、生产环境私网 DNS 预解析拦截与禁止跨站重定向。

## 八、快速开始与部署

### 1. 本地环境准备与全量测试

```bash
# 克隆仓库并进入目录
git clone <your-repo-url>
cd TaxTestOps

# 创建并激活虚拟环境 (Windows)
python -m venv .venv
.venv\Scripts\activate

# 安装全部依赖（使用清华镜像源加速）
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -e ".[dev]"

# 安装 Playwright 浏览器内核
python -m playwright install chromium

# 运行代码规范检查
ruff check .

# 执行全量质量门禁（自动跑全量套件并核查 15 项梯度覆盖率阈值）
python scripts/quality_gate.py
```

### 2. 启动服务与 Web 体验

```bash
# 终端 A：启动个税被测核心服务 (8000 端口)
python -m uvicorn tax_service.api.app:app --factory --port 8000

# 终端 B：启动测试管理平台 (8100 端口)
python -m uvicorn tax_service.platform.app:create_platform_app --factory --port 8100

# 终端 C：向测试平台初始化导入 15+ 条内置标准测试用例
python scripts/seed_platform.py

# 打开浏览器体验：
# - 被测个税测算界面：http://127.0.0.1:8000/ (包含 Swagger API 文档：http://127.0.0.1:8000/docs)
# - 测试平台监控看板：http://127.0.0.1:8100/ (包含平台 API 文档：http://127.0.0.1:8100/docs)
```

### 3. Docker Compose 一键多容器部署

```bash
docker-compose up -d --build
```
容器内自动编排 `taxtestops-service` 与 `taxtestops-platform`，内置自愈式健康探针。
